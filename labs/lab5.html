🔢 Lab 5: TCP Matrix Classifier

Build a client that creates a random square matrix, sends it through a TCP connection, and asks the server to identify its structural type.

Experiment05
ModelClient–Server
ProtocolTCP
ResultMatrix Type

🎯 Aim

To implement TCP client–server communication in which the client creates an N × N matrix with random integers in the range [1, 50], sends it to the server, and receives the matrix classification as a string.

🧩 The Mission

1️⃣ Input

Client reads the order N.

N × N

2️⃣ Generate

Populate the matrix using random values from 1 to 50.

rand()

3️⃣ Send

Transmit N and the matrix through a TCP socket.

send()

4️⃣ Classify

Server checks the matrix and returns a result string.

recv()

🔄 Communication Flow

CLIENT SERVER | | |--- TCP connection ------------------------>| | | |--- Order N ------------------------------->| |--- Matrix elements ----------------------->| | | Check matrix | | type |<-- "Upper/Lower/Diagonal/Other" -----------| | | |--- Close connection ---------------------->|

🧠 Classification Rules

  • Upper triangular: every element below the main diagonal is zero.
  • Lower triangular: every element above the main diagonal is zero.
  • Diagonal: every off-diagonal element is zero.
  • Other: the matrix does not satisfy any of the above conditions.

⚠️ Detective Twist

Think before coding: if every matrix element is generated only in the range [1, 50], no element can be zero. Therefore, for N > 1, a randomly generated matrix cannot normally be upper triangular, lower triangular, or diagonal.

Your task: first implement the specification exactly. Then explain this limitation in your observation. For meaningful testing, create separate instructor-approved test matrices containing zeros.

🖥️ Client Responsibilities

  1. Create a TCP socket.
  2. Connect to the server IP address and port.
  3. Read the matrix order N.
  4. Generate and display the N × N matrix.
  5. Send N followed by all matrix elements.
  6. Receive the classification string.
  7. Print the server's result and close the socket.

🗄️ Server Responsibilities

  1. Create a TCP socket.
  2. Bind it to a port and listen for a client.
  3. Accept the incoming connection.
  4. Receive N and the complete matrix.
  5. Check diagonal status first, then upper/lower triangular conditions.
  6. Send the classification as a string.
  7. Close the connected and listening sockets.

❓ Viva Questions

  1. Why is TCP suitable for sending a matrix?
  2. What is the purpose of bind(), listen() and accept()?
  3. Why should the client send N before the matrix?
  4. How does the server identify an upper triangular matrix?
  5. How does a diagonal matrix satisfy both triangular conditions?
  6. Why does classification order matter?
  7. What problem arises from generating values only in [1,50]?
  8. Can one call to recv() always be assumed to return all TCP data?
  9. What happens if client and server use different data representations?
  10. How would you extend the server to handle multiple clients?
