🕵️ Lab 1: Linux Network Detective

Build a network profile of your own Linux system using evidence, not copied output.

Experiment01
ModeIndividual
LevelFoundation
EvidenceNetwork Profile

🎯 Mission

Investigate the network identity and connectivity of your Linux machine. Create an evidence-based profile containing interface details, IP configuration, gateway, DNS resolution, path information and active connections.

🧠 Questions to Discover

  • Which interface carries your traffic?
  • What are your IPv4 address, prefix, MAC address and default gateway?
  • Can you reach a local gateway, a public IP and a domain name?
  • Which intermediate hops are visible?
  • Which TCP/UDP endpoints are active?

🚀 Investigation Route

1. Identify the machine
hostnamectl ip -brief address ip link show
2. Find the way out
ip route
3. Test connectivity in three stages
ping -c 4 <default-gateway> ping -c 4 8.8.8.8 ping -c 4 example.com
4. Follow the path
traceroute example.com mtr -r -c 10 example.com
5. Ask DNS
nslookup example.com
6. Observe local activity
ss -tuln nmcli device status
7. Optional live observation
sudo iftop -i <interface> sudo tcpdump -i <interface> -c 10

🏁 Student Challenge

Network Health Verdict: Classify the connection as Healthy, Partially Reachable, DNS Problem or High Latency. Support your verdict with at least three observations.

❓ Viva

  1. Why can ping to an IP succeed while ping to a domain fails?
  2. Why is ip preferred over ifconfig?
  3. What does a default gateway do?
  4. Why can traceroute show * * *?
  5. What is a listening socket?
